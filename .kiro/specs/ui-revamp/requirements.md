# Requirements: Gestalt UI revamp (F12)

Audience: people who find paper forms difficult, including English/Hindi users and their helpers. Outcome: understand where to begin, answer one field, check the document, and export without competing visual priorities. Scope covers the entry screen and all five workspace steps; no new backend, provider, publication or data collection.

1.1 WHEN the entry screen opens THE SYSTEM SHALL group upload/camera controls and supported formats within one starting region, with returning-code and blank-page actions subordinate to it.
1.2 WHEN sample forms are shown THE SYSTEM SHALL use repeated card structure and preserve fictional/demo labels and working download links.
2.1 WHEN a form is active THE SYSTEM SHALL connect five numbered step controls visually and identify the current step with text, shape and `aria-current`.
2.2 WHEN a question is active THE SYSTEM SHALL group its label, requirement, hint, input, validation and forward action in a shared region, with the document visually separate.
2.3 WHEN review or export is shown THE SYSTEM SHALL distinguish answer review, PDF output, encrypted-code output and optional model settings through grouping and hierarchy.
3.1 THE SYSTEM SHALL preserve existing mapping, OCR, PDF, code refill, signature, consent, cancellation and privacy behaviour.
3.2 THE SYSTEM SHALL keep all controls keyboard-accessible, both UI languages usable, and layouts within a 320px viewport at default text size.
3.3 WHILE reduced motion is requested THE SYSTEM SHALL disable decorative and transition motion; essential state changes SHALL remain visible without animation.
3.4 THE SYSTEM SHALL self-host new fonts with their licences and attribution, maintaining text/control contrast thresholds from the accessibility spec.
4.1 THE SYSTEM SHALL verify the entry, check, answer, review and export screens at desktop/mobile sizes and exercise the no-LLM journey before claiming completion.
